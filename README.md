# NLP Analysis of Consumer Complaints

This repository contains the development phase of IU course **DLBDSEDA02,
Task 1**. It applies natural language processing and unsupervised topic
modelling to consumer complaint narratives.

## Objective

The objective is to identify prevalent complaint themes and compare the topic
structures produced by Latent Dirichlet Allocation (LDA) and Non-negative
Matrix Factorization (NMF).

## Dataset

The analysis uses the [Consumer Complaint Database on Kaggle](https://www.kaggle.com/datasets/selener/consumer-complaint-database).
The original CSV is not stored in this repository because of its size. A
reproducible sample of 10,000 unique, non-empty complaint narratives is created
with `random_state=42`.

## Methodology

1. Missing and duplicate narratives are removed.
2. Text is lowercased and URLs, email addresses, numbers, punctuation and
   masked `XXXX` content are removed.
3. NLTK-compatible tokenization, stopword removal and lemmatization produce
   clean text.
4. CountVectorizer creates a Bag-of-Words matrix for LDA.
5. TfidfVectorizer creates a weighted matrix for NMF.
6. The topic count is identified through repeated 80% subsampling and
   term-centric stability analysis for `k=2` to `k=20`.
7. Topics are matched with the Hungarian algorithm and compared with ranked
   Average Jaccard similarity.
8. The selected LDA and NMF solutions are compared using topic words,
   prevalence and model agreement.

The stability procedure addresses the risk of selecting a topic count only by
subjective inspection. Comparable scores are resolved in favour of the smaller
solution when topic diversity remains acceptable.

## Run online in Kaggle

1. Open the [public Kaggle notebook](https://www.kaggle.com/code/leosteiner0/notebookf59b1fdbbe).
2. Select **Copy & Edit** if necessary.
3. Add the Consumer Complaint Database through **Add Input**.
4. Use a standard CPU session and select **Restart Session**.
5. Select **Run All**.
6. Confirm that the final cell reports:

   ```text
   DEVELOPMENT-PHASE ANALYSIS COMPLETED AND VALIDATED
   ```

7. Download the completed notebook and the generated files under
   `/kaggle/working`.
8. Replace this initial README and requirements file with the versions generated
   by the successful Kaggle run, then upload the complete `results` folder.

The notebook is designed to run without internet access. If optional NLTK data
or Gensim coherence cannot be used, a documented fallback allows the core
stability analysis to continue.

## Outputs

The notebook generates:

- data-cleaning and quality summaries;
- Bag-of-Words and TF-IDF comparison tables;
- a topic-count stability table and selection diagram;
- LDA and NMF topic-word tables and diagrams;
- topic-prevalence tables and diagrams;
- an LDA–NMF topic-agreement heatmap;
- product-distribution evidence;
- a machine-readable JSON result summary;
- a README containing the actual results from the completed run; and
- a version-pinned `requirements.txt` from the executed Kaggle environment.

## Limitations

- Sampling may exclude rare complaint themes.
- Stability measures reproducibility, not guaranteed semantic usefulness.
- Preprocessing choices affect the resulting topics.
- Automatic labels summarize top terms and still require human interpretation.
- The selected topic count applies to this sample and modelling configuration.
